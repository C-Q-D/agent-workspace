## 1. 本轮真正要解决的问题

AgentWorkspace 已经具备真实 PowerShell/ConPTY、多窗口动态矩阵、单窗口放大、稳定
`workspaceRoot`、文件与代码行引用、聚焦仓库 Review、恢复和 16GB 性能门禁。当前主要
摩擦不是“终端能不能用”，而是用户仍需在 AgentWorkspace、外部编辑器、文件管理器、
Git 工具和多个终端之间频繁切换。

本方案按用户价值固定为五个优先级：

1. **P1：完成日常编辑与双向导航闭环。** 用户不离开 AgentWorkspace 即可完成小修改、
   保存、冲突处理、Diff 往返、终端路径跳转、输出引用、快速切换与核心键盘操作。
2. **P2：降低同时管理多个 AI 任务的人脑负担。** 每个窗口有任务信息、Notes、可靠状态、
   Dashboard、分组、排序、布局预设和受控批量操作。
3. **P3：减少上下文搬运成本。** 支持批量路径、图片、提示模板、常用命令、Markdown
   Source/Preview，以及 Codex/Claude 官方会话入口。
4. **P4：让 Git 审查与本地写操作更安全。** 支持分支/worktree 总览、全局只读状态、
   明确触发的 stage/unstage、本地 commit、Checkpoint、受控恢复和可信时间线。
5. **P5：保证长时间自用时可恢复、可解释、不卡顿。** 支持元数据快照、崩溃恢复、资源
   面板、16GB 提示、配置损坏恢复、诊断、长稳、受预算约束的搜索实验和工作摘要。

每个优先级完成后都形成一个可以立即使用的增量版本，不要求等待后续所有优先级完成。

## 4. 固定架构与资源约束

### 4.1 状态和所有权

1. `WindowSession` 是稳定工作区聚合根。工作区任务元数据、Notes、编辑标签和干净/脏缓冲
   的归属都以 `workspace_id` 为键，不能以易变化的 `active_idx` 或 UI Entity ID 为事实源。
2. `DisplayState` 继续决定 Grid、Focused、Review、Settings。Files、Editor、Markdown
   Preview 等只是 Focused 内右侧 Context 的子表面，不能形成与 `DisplayState` 竞争的
   第二状态机。
3. 所有异步结果必须携带 `workspace_id + workspaceRoot + generation`，完成时三者都匹配
   才能落入 UI。
4. Grid 允许保留有界的休眠元数据和未保存缓冲，但必须释放文件 watcher、编辑器渲染实体、
   Diff watcher、资源 sampler、目录扫描任务和 Git 轮询。
5. Review 与 Editor 不得同时持有两个仓库刷新器。Editor 保存后复用 Review 的事件或显式
   一次刷新。

### 4.2 编辑器边界

- 只编辑 UTF-8 文本；UTF-8 BOM 可编辑并保真保存。
- 单文件读取上限为 1 MiB。二进制、非 UTF-8、超大文件和无法读取文件进入只读说明与
  “用外部编辑器打开”回退。
- 每工作区最多 8 个标签，全应用最多 24 个已加载标签，已加载正文软预算 16 MiB。
- 达到预算时先按 LRU 回收干净的休眠标签；脏缓冲永不静默丢弃。没有可回收空间时阻止
  打开并解释原因。
- 新插入行使用原文件主换行风格；保留 UTF-8 BOM、最终换行状态和未修改正文。混合换行
  必须有真实测试，不能无提示地全文件重写。
- 不支持 LSP、定义跳转、代码补全、格式化、调试和插件。
- 关闭标签、关闭窗口、切换会话、进入 Grid、退出应用和异常恢复均不得静默丢失脏缓冲。

### 4.3 引用、图片和命令边界

- 终端选择快照最多保存 64 KiB；预填 CLI 时最多 32 KiB，超限必须给出明确截断标记与
  二次选择入口。
- 文件/目录/行/图片引用只插入目标终端输入区，不追加回车。
- 图片附件写入 `%USERPROFILE%\.agent-workspace\attachments\<workspace-id>\`，不默认写入
  用户 Git 仓库。单文件 10 MiB，总缓存 200 MiB，按未被引用的最旧附件清理。
- Prompt 模板单项最多 8 KiB；常用命令单项最多 4 KiB。默认动作是“插入”，只有用户明确
  点击独立的“运行”按钮才提交命令。
- “最近命令”只记录通过 AgentWorkspace 常用命令入口明确运行的内容，不截获全部键盘输入，
  不伪装成 PowerShell 历史。

### 4.4 Git 安全边界

- 所有 Git 写入都重新解析并校验当前 `workspaceRoot`、worktree root 与 git dir。
- stage、unstage、commit、checkpoint 恢复都必须由当前用户显式点击；不能从 Hook 或
  Agent 状态自动触发。
- 本方案永不执行 push、force、reset --hard、clean 或删除未跟踪文件。
- Checkpoint 不是自动 commit；数据和补丁放入 `.agent-workspace` 用户数据目录。
- 恢复 Checkpoint 前必须展示将修改的文件，检测工作树漂移，并允许取消。
- 没有可靠 Hook 关联时，时间线只写“工作区发生变化”，不能标成“Claude 修改”。

### 4.5 性能硬门禁

- A026 的 16 个空 PowerShell/ConPTY 基线是对照事实；任何阶段不得用“机器感觉不卡”替代
  采样。
- Grid 的新增外壳工作集不得比 A026 同场景增加超过 5%，Idle CPU 中位数保持不高于 1%。
- Focused 打开 8 个上限内文本标签时，新增应用工作集预算不超过 32 MiB。
- 20 个工作区快速搜索 P95 不高于 50 ms；工作区切换 P95 不高于 100 ms。
- 禁止每 workspace 高频 timer。资源面板只在可见时采样，默认周期不短于 2 秒，隐藏后
  完全停止。
- 禁止后台仓库全文索引。跨工作区内容搜索必须先通过独立性能实验；实验不通过即记录
  no-go，不得绕过门禁实现。
- 每个真实 Windows 验收结束后必须证明 PowerShell、ConPTY、helper 和应用子进程零残留。

## 6. 每个代码原子的强制执行协议

### 6.1 开始前

每个原子都必须依次执行：

1. 重新读取本方案、`docs/ai-project/项目工作台.md`、`app/AGENTS.md` 和
   `app/docs/当前开发状态.md`。
2. 进入 `app`，确认分支、upstream、`git status --short` 和最近提交；不得覆盖用户已有修改。
3. 读取原子卡列出的源码与测试；用 `rg` 再确认路径和符号仍存在，禁止只凭旧文档修改。
4. 在动代码前写一份 5～10 行的“本原子实施计划”：当前事实、预期红灯、最小变更、真实验证、
   性能/回归边界和回滚方式。
5. 若实际事实与原子卡冲突，先更新事实记录并暂停该原子；不能硬套路径。

### 6.2 红灯、实现和测试

1. 能用自动测试固定的行为必须先写失败测试。测试使用真实临时目录、真实文件、真实 Git
   仓库、真实进程或纯值模型；mock 不能作为最终验收证据。
2. 只实现让当前红灯转绿的最小代码。不顺手重命名大模块、不清理无关警告、不升级依赖。
3. 所有新增或修改的手写代码遵守仓库要求，使用中文文件级、类型、字段、方法、边界与性能
   注释；同步删除过期英文事实说明。
4. 至少运行定向测试、相关模块回归和格式检查。每三个原子或单元边界运行完整
   `paneflow-app` 测试、`paneflow-config` 测试与 flex 布局测试。
5. UI、PTY、文件、Git、进程、性能和恢复行为必须有真实 Windows Release 验收；单元测试
   通过不能替代真实路径。

### 6.3 失败时

发现 Bug 或测试失败后：

1. 立即停止猜测式修改。
2. 固定最小复现，采集日志、输入、输出、退出码、PID/句柄和文件前后状态。
3. 写出“直接原因、根本原因、为什么现有测试没挡住、最小修复边界”。
4. 只有根因被证据支持后，才能建立 `E原子号-F01` 修复原子并写修复计划。
5. 修复原子独立测试、提交和推送；原原子随后从红灯重新完整验收。
6. 未找到根因时保持失败状态并停止，不得通过放宽断言、延长 sleep、重试循环或删除测试
   制造绿灯。

### 6.4 提交、推送和检查点

1. 每个原子只含一个行为理由，测试通过后检查完整 diff。

- **红灯**：无 HEAD、linked worktree、符号链接、超大/二进制、路径越界、100/500 MiB 边界、
  manifest 损坏。
- **最小实现**：先定义纯 schema 和真实文件 capture plan，不实现恢复；内容按哈希去重可后置，
  不能先引入复杂对象库。
- **验证**：manifest 不包含终端正文、Prompt、token 或项目外文件。

#### E110：创建、列出、命名和清理 Checkpoint

- **结果**：用户明确点击后后台捕获当前工作树/index；列表显示时间、名称、HEAD、文件数、
  大小和未捕获项；按保留规则清理最旧非固定项。
- **红灯**：捕获中外部修改、磁盘空间不足、取消、同名、应用退出、固定项达到总配额。
- **最小实现**：每文件复制前后核对 fingerprint，漂移则该 checkpoint 整体失败并清理临时目录。
- **验证**：失败不留下可见半 checkpoint；项目 Git 状态不因捕获变化。

#### E111：生成恢复预览与漂移判定

- **结果**：选择 checkpoint 后显示将恢复、当前已变化、缺失、额外新建和无法安全处理的文件；
  默认不勾选额外未跟踪文件。
- **红灯**：HEAD/index 变化、文件在捕获后再修改、路径改成 junction、checkpoint 内容缺失。
- **最小实现**：纯 restore plan 在后台读取、带 generation；不在预览阶段写磁盘。
- **验证**：每个计划动作有来源哈希、当前哈希和可取消理由。

#### E112：执行受控恢复并隔离额外未跟踪文件

- **结果**：用户二次确认后恢复所选捕获文件和 index；明确选择移除的额外未跟踪文件被移动到
  quarantine，可再次找回，绝不直接删除。
- **红灯**：恢复中某文件锁定、部分写入、磁盘满、外部并发修改、quarantine 同名。
- **最小实现**：先写 staging 临时目录并再次校验；按计划逐项执行，失败给出已完成/未完成清单；
  不声称跨多文件绝对事务。
- **验证**：原始文件或 quarantine 中总能找到用户数据；不执行 reset/clean。

#### E113：Checkpoint/恢复/撤销真实总验收

- **结果**：真实仓库在 Agent 修改前建 checkpoint，随后产生修改/删除/重命名/未跟踪和
  staged 变化，预览并恢复到预期状态。
- **允许修改**：新增 `scripts/运行Windows代码Checkpoint验收.ps1` 和报告。
- **验证**：CRLF/BOM/二进制/大文件未捕获、锁失败、外部漂移、quarantine、配额、重启和

### 12.4 P4-04：有来源可信度的活动时间线（E114～E117）

本单元读取 `S-AGENT`、`S-GIT`、`S-SESSION` 和 E048 任务元数据。时间线记录“应用已观察到

#### E114：定义活动事件与来源可信度

- **结果**：事件类型限于窗口/任务/命令入口/可靠 Hook/Git snapshot/Editor save/

  `System`。
- **红灯**：无 Hook 文件变化、同 root 两 Agent、时钟回拨、事件重复、超长摘要。
- **最小实现**：只有 E059 binding token 覆盖的区间可标 `VerifiedAgent`；其他写“工作区变化”。
- **验证**：事件正文有长度上限且不保存终端完整输出、文件正文或 Prompt。

#### E115：实现有界时间线持久化与轮换

- **结果**：每 session 最多 1,000 条、全应用最多 10,000 条或 20 MiB，先到者触发最旧轮换；

- **红灯**：事件洪泛、应用崩溃中写、旧版本迁移、workspace 删除、磁盘只读。
- **最小实现**：批量/去抖后台写，关键 commit/checkpoint 事件同步入队；不阻塞 GPUI。
- **验证**：轮换后稳定 ID 和来源不变，损坏文件有备份或跳过记录。

#### E116：实现时间线查看、过滤和跳转

- **红灯**：目标文件删除、workspace 关闭、checkpoint 已清理、Git commit 不存在、过滤空。
- **最小实现**：虚拟/分页渲染，单页不超过 200 行；目标失效显示历史事实而非报错崩溃。
- **验证**：10,000 条上限下打开/滚动性能，关闭后释放渲染缓存。

#### E117：可靠归属与多窗口真实总验收

- **结果**：两个真实 CLI/hook helper、用户 Editor、Git commit 和无 Hook 外部脚本同时工作，
  时间线只对可证明事件标 Agent。
- **允许修改**：新增 `scripts/运行Windows活动时间线验收.ps1` 和报告。
- **验证**：乱序、断开、A/B 同 root、重启、轮换、跳转、资源和零残留。
- **阶段门**：E097～E117 完成后，Git 写操作具备显式边界和恢复路径，但产品仍绝不代替用户
  执行 push 或危险清理。

## 13. P5：恢复、资源治理与长期自用（E118～E139）

### 13.1 P5-01：元数据快照、草稿日志与崩溃恢复（E118～E123）

本单元读取 `S-SESSION`、`S-DATA`、E025 标签状态、E048 任务元数据、E068 预设和 E109
Checkpoint。Snapshot 恢复的是窗口/视图/任务元数据并创建新 PTY；Checkpoint 恢复的是文件

#### E118：定义 Workspace Snapshot schema 与恢复边界

- **结果**：快照可保存窗口稳定 ID 映射、root、名称、顺序、分组、任务、Notes、标签路径/
  光标、布局预设、活动视图和官方 CLI 会话提示；明确排除 PID、PTY、句柄、终端缓冲和

- **红灯**：旧/未来版本、20 workspace、失效 root、重复 ID、已删除标签、快照中出现运行态
  字段。
- **最小实现**：schema 与 current session 可共享可恢复子类型，但快照有独立版本和 ID；
  不能直接序列化 PaneFlowApp。
- **验证**：敏感运行对象的编译/序列化契约测试失败。

#### E119：实现手动创建、命名、列出和删除 Snapshot

- **结果**：用户可在 Dashboard 明确创建元数据快照，看到窗口数、任务、时间和缺失目录；
  默认最多 20 个，删除前确认。
- **红灯**：创建中修改任务/顺序、重名、磁盘只读、超限轮换、manifest 损坏。
- **最小实现**：后台原子写，先捕获不可变纯数据；快照不触发 Git 或终端命令。
- **验证**：应用和项目状态除用户数据文件外不变。

#### E120：生成 Snapshot 恢复计划而不立即变更

- **结果**：预览将保留、创建、关闭、跳过的窗口，失效 root、达到 20 上限、脏标签和当前
  运行进程；默认不关闭现有窗口。
- **红灯**：当前与快照同 root/不同 ID、同 ID/root 变化、快照窗口失效、脏缓冲。
- **最小实现**：纯 restore plan；用户可选择“合并到当前”或“先按正常关闭流程替换”，后者
  仍经过 DirtyBufferGuard。
- **验证**：预览阶段零写入、零 PTY 创建/关闭。

#### E121：按计划恢复元数据并创建新 PTY

- **结果**：用户确认后复用/新建 WindowSession，恢复可恢复元数据；所有需要启动的终端是
  新 PID；CLI 对话只提供 E095 官方恢复入口。
- **红灯**：中途目录消失、Git 初始化失败、某 PTY 启动失败、用户取消、部分恢复。
- **最小实现**：逐 session 调用 WorkspaceLifecycle；失败项独立，成功项不因另一项回滚。
- **验证**：报告明确旧/新 PID，不显示“进程已恢复”等误导文案。

#### E122：建立脏编辑草稿日志和不干净退出标记

- **结果**：脏缓冲以去抖、版本化、每文档有界草稿写入用户数据；正常保存/丢弃/退出清理；
  应用启动能识别上次是否异常退出。
- **红灯**：快速输入、崩溃在临时写期间、草稿超 1 MiB、文档外部变化、多个 workspace、
  正常退出不误报。
- **最小实现**：草稿包含原文件路径、加载 fingerprint、正文、BOM/换行事实和时间；不自动
  回写项目。
- **验证**：写入去抖不阻塞 GPUI，Grid 无 timer；草稿总预算 32 MiB，超限明确提示。

#### E123：真实进程强杀、草稿选择恢复与损坏隔离

- **结果**：强制终止 Release 后重启，用户看到可恢复草稿和元数据，能比较磁盘版本、恢复到
  Editor 或丢弃；单草稿损坏不影响其余。
- **允许修改**：新增 `scripts/运行Windows崩溃恢复验收.ps1` 和报告。
- **验证**：强杀发生在输入、保存、Snapshot 写入、切 workspace 四时点；无项目自动写入；
  新 PTY、外部冲突、32 MiB 预算、损坏备份和零残留。

### 13.2 P5-02：应用与子进程资源面板（E124～E129）

本单元读取 `workspace/pid_resolve.rs`、`terminal/pty_session.rs`、现有进程树关闭代码、Windows
性能 probe 和 E059 binding。资源信息用于解释与提醒，不自动杀进程、不暂停 Agent。

#### E124：审计并探测 Windows 进程树与资源 API

- **结果**：用真实 probe 确认如何从应用 PID、ConPTY 根 PID 和已验证 Agent PID 获取工作集、

- **红灯**：PID 重用、AccessDenied、进程瞬时退出、Job Object/ConPTY 子孙、32/64 位差异。

- **验证**：隐藏 60 秒采样计数保持不变，句柄回到基线。

#### E126：区分应用、shell、CLI 和其他子进程展示

- **结果**：Dashboard 资源页显示应用外壳、每窗口 PowerShell/CLI/其他子孙的 CPU、内存、
  PID 和更新时间；无法归类时明确“其他/未知”。
- **红灯**：普通 shell、Codex/Claude、自定义命令、多层子进程、已退出、AccessDenied。
- **最小实现**：CLI 归属只使用 E059 binding 或可靠可执行文件身份，不按窗口标题猜测。
- **验证**：状态不只靠颜色，单位与总和可解释，不声称等于整机任务管理器所有口径。

#### E127：增加 16GB 友好的分级提醒

- **结果**：根据物理内存、应用+子进程总量、单 CLI 异常增长和窗口数给出信息/警告；只建议
  聚焦、关闭或检查，不自动操作。
- **红灯**：16/32/64GB、内存统计不可用、瞬时峰值、采样首轮、用户已关闭提示。
- **最小实现**：连续三次超过阈值才警告，默认总提交内存或物理内存 70% 为警戒参考；
  阈值和口径写清楚，不能把应用外壳 256 MiB 预算套到 CLI 子进程。
- **验证**：负载下降后状态恢复，不产生 toast 风暴。

#### E128：固定 sampler、面板和窗口生命周期释放

- **结果**：关闭面板、workspace、应用以及崩溃恢复后无采样任务、PROCESS 句柄或旧 PID 缓存。
- **红灯**：面板打开时批量关闭、PID 重用、目标拒绝查询、应用退出期间采样回调。
- **最小实现**：一个 owned sampler handle 和统一 stop/drop；回调继续走 generation。
- **验证**：Windows 句柄计数、任务计数和 100 次开关压力测试。

#### E129：16 工作区资源分账与长输出真实验收

- **结果**：16 个真实 PowerShell，其中 Codex/Claude 可用时各一个，持续输出和子进程负载下
  资源分账稳定、提醒合理。
- **允许修改**：新增 `scripts/运行Windows资源面板验收.ps1` 和报告。
- **验证**：面板开/关 CPU 差、2 秒节奏、进程树准确、PID 重用、句柄、内存和零残留。

### 13.4 P5-04：长稳、搜索性能实验与开发摘要（E135～E139）

  不建立索引、不默认搜终端全部 scrollback。
- **通过门槛**：普通查询首批结果 P95≤500 ms、取消≤200 ms、额外工作集≤64 MiB、关闭后
  Idle CPU 回到≤1%；任一不满足即 no-go。
- **验证**：结构化报告必须同时保留通过与失败样本、整机/应用/搜索子进程分账、命令次数、
  取消延迟和关闭零残留，不能只记录最好一轮。

#### E138：按实验结论交付有界搜索或正式 no-go

- **结果**：只允许“预算通过并交付有界搜索”或“预算未通过并正式保持关闭”两种完成态；
  两者都消除实验代码和产品状态之间的含糊。
- **通过路径**：实现显式打开、明确来源、结果分页、取消、generation 校验和跳转；单次最多
  500 结果，查询结束释放进程/缓存。
- **不通过路径**：提交 no-go 决策、保留现有窗口元数据快速搜索，只允许用户以后手动重开实验；
  不把实验代码编进默认产品。
- **红灯**：结果来自旧查询、跨 workspace 串台、文件变化、`rg` 不存在、路径越界、关闭页面。
- **最小实现**：严格按 E137 结构化门槛选择一条路径；禁止通过降低样本规模、延长门槛或保留
  默认关闭但仍常驻的索引器制造“通过”。
- **验证**：无论哪条合法路径，都必须有提交、报告、性能证据和明确产品状态，禁止标“部分完成”。

#### E139：导出开发会话摘要并完成自动区间总验收

- **结果**：用户可导出一个有界 Markdown 摘要，包含窗口任务、可靠状态时间线、通过应用运行
  的常用命令、Git/Checkpoint/Snapshot 摘要、资源峰值和未解决错误；不含文件/终端全文。
- **红灯**：部分 workspace 已关闭、时间线轮换、Git 未加载、长稳报告缺失、导出失败。
- **最小实现**：从已有结构化事实组合，不再建记录器；导出前可取消勾选栏目。
- **验证**：运行 P1～P5 所有阶段总验收、完整 Rust/flex 测试、Release 构建、1/9/16 性能、
  两小时场景结果复核和零残留。
- **自动执行退出门**：E001～E139 必须全部有测试、提交、远端 SHA 和检查点。完成后停止，
  不得自动进入 E140。

## 14. 人工与外部环境关口（E140～E144）

这些原子故意放在最后。它们需要用户账号、真实任务、主观体验或产品方向决定。无人值守 Goal
必须停在本节之前，向用户报告自动区间完成情况和每个关口所需操作。

### E140：真实登录 Codex CLI 端到端

- **需要用户**：当前 Windows 用户已安装并登录 Codex CLI，允许用一个新建临时 Git 仓库执行
  一次无敏感内容的真实任务。
- **结果**：验证启动、Prompt/文件/行/图片引用、Hook（若官方支持）、输出跨窗、Editor 冲突、
  Review、Checkpoint 和官方 resume。
- **通过**：任务真实修改文件并完成审查；所有 unsupported capability 如实降级；无账号/
  会话内容写入验收报告。

### E141：真实登录 Claude Code CLI 端到端

- **需要用户**：当前 Windows 用户已安装并登录 Claude Code，允许相同类型临时仓库任务。
- **结果/通过**：与 E140 同一矩阵验证 Claude 的实际命令、引用、Hook 与 resume，不能用
  Codex 结果代替；记录 CLI 版本差异和明确不支持项。

### E142：图片、剪贴板和应用截图人工体验验收

- **需要用户**：实际使用 Windows Snipping Tool、剪贴板图片和当前 AgentWorkspace 窗口截图，
  确认预览、附件路径、跨窗预填和清理是否符合习惯。
- **结果**：只修复可复现 Bug；若用户希望支持任意外部窗口/区域直接捕获，应作为新产品单元
  重新拆分，不能扩进 E080。

### E143：用户中心的整体可用性复查

- **需要用户决定**：右栏默认宽度、默认快捷键、Dashboard/Terminal 默认展示、分组与预设
  入口、Git 写操作确认强度、资源提醒阈值。
- **执行方式**：AI 先给出真实录屏/截图、操作次数、性能和错误数据，再逐项请用户选择；禁止
  一次抛出大量抽象问题。
- **结果**：确认项写入产品决定；任何改动重新拆独立修复原子并测试/提交/推送。

### E144：当前用户自用版本最终验收与下一路线决定

- **结果**：汇总 E001～E143 的功能、提交、测试、性能、已知限制和 no-go；用户实际使用一段
  时间后决定：
  1. 继续修复自用摩擦；
  2. 恢复公开发布路线并重排旧 A027 以后原子；
  3. 暂停在稳定自用版本。
- **完成条件**：只有用户明确接受当前自用版本且不存在 P0/P1 数据丢失、串 workspace、
  进程残留或性能红灯，才能把本方案标记完成。

## 15. 阶段完成定义

| 阶段 | 完成原子 | 此时用户实际得到的能力 | 可否停止长期使用 |
|---|---|---|---|
| BASE | E001～E004 | 可恢复的新事实源与稳定基线 | 仅开发准备 |
| P1 | E005～E047 | 内部小编辑、保存冲突、Diff 往返、终端双向引用、快速切换和键盘闭环 | **可以，第一推荐停靠点** |
| P2 | E048～E072 | 任务 Notes、Dashboard、可靠状态、分组、预设和批量管理 | 可以，适合多任务日常使用 |
| P3 | E073～E096 | 批量文件、图片、模板、常用命令、Markdown 和 CLI 官方恢复入口 | 可以，上下文搬运更完整 |
| P4 | E097～E117 | Git 拓扑、全局状态、stage/commit、Checkpoint 和可信时间线 | 可以，形成安全开发工作台 |
| P5 自动区间 | E118～E139 | 崩溃恢复、资源治理、诊断、长稳、条件搜索和摘要 | 可以，达到成熟自用候选 |
| 人工关口 | E140～E144 | 真实 Codex/Claude 与用户体验确认 | 用户确认后最终完成 |

任何阶段只有在该区间所有原子真实测试、独立提交、推送和阶段总验收都通过后才可标记完成。
某个功能代码存在但缺真实 Windows、性能或失败路径证据时仍为“进行中”。
