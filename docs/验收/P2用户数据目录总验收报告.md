# P2-04 用户数据目录总验收报告

## 结论

P2-04 于 2026-07-19 验收通过。AgentWorkspace 的 Windows 发布版自有数据统一位于 `%USERPROFILE%\.agent-workspace`，调试版位于 `%USERPROFILE%\.agent-workspace-dev`。设置、会话、内部状态、稳定辅助程序、可重建缓存和诊断日志具有明确且互不重叠的生命周期目录；现有生产写入已经归位，真实 Release、MSI 和便携版共同证明启动、缓存重建、升级、卸载与发行形态切换不会越界删除 durable 数据。

P2-04 没有增加轮询、常驻线程、定时器或默认文件日志。路径布局是纯计算；缓存只在对应功能首次使用时重建；遥测安装 ID 使用一次性 `create_new` 写入解决并发首次启动，不形成持续 I/O。完整配置、遥测、MCP 和桌面应用回归全部通过，适合继续遵守 16 GB 内存设备优先的低开销约束。

机器汇总见 [P2-04 运行结果](Windows用户数据边界数据/P2-04-20260719-201936/运行结果.json)。

## 最终目录契约

| 目录 | 生命周期 | 当前内容与行为 |
| --- | --- | --- |
| `config/` | durable | `settings.json`；用户显式设置，升级和卸载保留 |
| `sessions/` | durable | `workspaces.json` 与损坏备份；工作区恢复状态，升级和卸载保留 |
| `state/` | durable | 遥测安装 ID 等内部持久状态；不与用户设置混放 |
| `bin/` | durable | 被外部 CLI 配置稳定引用的 MCP/Hook 二进制；清缓存不删除 |
| `cache/` | rebuildable | Markdown 状态、通知图标、shell 集成、版本化 helper、更新暂存；可整体删除并按需重建 |
| `logs/` | diagnostic | Windows 更新、relay 和显式 Hook 诊断；与缓存分离，不默认高频写入 |

程序本体不属于用户数据：安装版位于 Program Files，便携版位于用户解压目录。用户 Git 项目、Codex/Claude 自有配置和旧 Paneflow 数据也不属于 AgentWorkspace 自有目录。

## 真实 Windows 场景

### Release 启动与退出

- 使用真实 Windows x64 Release、唯一命名管道、PowerShell/ConPTY 和真实 Git 工作区。
- 应用自有写入只进入隔离用户的 `.agent-workspace`；PowerShell 自身的 AppData 写入单独分类为外部运行时。
- 非 Git 工作区真实执行本地 `git init`；开发者原有数据、旧 Paneflow 与外部哨兵均不变。
- 正常关闭后应用、PTY 和 helper 进程树归零。

### MSI 初装、升级与卸载

- 真实完成 0.7.10 初装、0.7.11 MajorUpgrade 和 0.7.11 卸载，三个事务退出码均为 0。
- `config / sessions / state / bin`、缓存、日志、旧 Paneflow、无关用户文件和外部项目共 10 类哨兵在升级和卸载后字节不变。
- 卸载只移除程序目录、开始菜单、卸载注册项与系统 PATH 条目，不删除 `.agent-workspace`。

### 安装版与便携版联合边界

- 安装版创建的工作区会话可被便携版读取，便携版创建的会话也可被安装版读取。
- 安装版和便携版分别在删除 `cache/` 后重建同一 `shell/pwsh/osc7.ps1`；缓存清单完全一致。
- 两次缓存重建期间 `config / sessions / state / bin` 完整目录清单及 `logs/` 均保持不变。
- 便携程序目录运行前后载荷不变且未产生 `.agent-workspace`；删除便携目录与卸载 MSI 均不影响用户数据。

## 源码与性能复核

以 P2-03 完成提交 `0132940` 为基线审计 P2-04 的生产代码增量：

- 所有 AgentWorkspace 自有路径由 `UserDataLayout` 或其统一运行时入口派生。
- 没有新增 `dirs::cache_dir`、`dirs::data_local_dir`、系统临时目录或旧 Paneflow 路径构造器；相关文本只存在于禁止回退的测试断言。
- 没有新增轮询、常驻线程、定时器、默认文件日志器或后台目录扫描。
- 唯一匹配到的新增 `OpenOptions` 是遥测 ID 的一次性 `create_new`，已有文件走读取快路径，并发竞争会读取胜出文件。
- Windows 更新日志只在显式更新流程中写入 `logs/update/`；Hook 日志仍只在用户设置 `PANEFLOW_HOOK_LOG` 时写入指定位置。

因此本单元没有引入持续 CPU、线程或内存负担，也没有为了目录分层增加空目录预创建和常态磁盘 I/O。
