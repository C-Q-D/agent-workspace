# A019 辅助页面与恢复迁移验收

## 验收结论

A019 已把 Review、Settings 和启动恢复接入单一 `DisplayState` 转换模型：

- 聚焦窗口进入 Review 后，Review 状态必然携带同一 `FocusedContext`。
- 退出 Review 确定返回原聚焦窗口。
- 从聚焦或网格打开 Settings 后，关闭时分别返回原聚焦窗口或网格。
- Settings 可见期间切换、恢复或关闭工作区，只更新被保存的返回状态，不制造非法组合。
- 启动时旧会话模式只作为兼容输入读取，公开展示状态始终从合法网格状态恢复。
- Review、Settings、启动恢复和关闭当前窗口不触发 PTY 重启。

当前代码尚无独立 Diagnostics UI 或展示状态，因此不存在可迁移的旧诊断入口；
正式 Windows 环境诊断由计划 A049～A058 引入，并须直接接入本状态模型。

生产路径保留一个临时兼容桥，将单一展示状态投影到旧
`mode`/`settings_section` 读取字段；A020 将删除这两个旧字段与兼容投影。

首次运行保存在：


应用已经按当前规则在隔离用户目录写入 `.agent-workspace` 数据，但旧脚本仍连接
硬编码的 `paneflow` 管道，并使用旧 AppData 配置/会话位置和旧进程名。第一次偏离
发生在验收客户端连接端点，生产 Review 状态尚未被调用。

证据同时排除了启动失败和状态机回归：Release 进程成功运行，统一数据目录已产生
helper 与会话文件；源码中的当前默认管道为 `agent-workspace`。因此没有调整生产
代码、等待时间或 Review 断言，只迁移脚本身份。使用独立
`agent-workspace-review-*` 管道复验后全部通过。

## 范围边界

本原子不恢复 Agents/Rosetta 公开页面，不改变 PTY 创建、Shell、工作区目录或 Git
生命周期，不增加后台轮询。旧 `AppMode` 字段和剩余只读分支由 A020 删除。
