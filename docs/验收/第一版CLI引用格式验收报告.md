## 行为验收结果

1. 放大工作区后，右侧文件栏提供 Common、Codex、Claude 和 Shell 四种引用格式选择。
2. 文件右键菜单的 `Add Path to Prompt` 按当前选择生成引用，并写入当前放大终端。
3. Common 与 Codex 第一版均生成 `f:相对路径`；OpenAI 官方文档未定义稳定的本地文件 mention 协议，因此没有虚构 Codex 私有格式。
4. Claude 生成 `@相对路径`，PowerShell 生成单引号包裹的绝对 Windows 路径。
5. 行选择器通过普通点击和 Shift 点击选择真实文件第 2～4 行，生成 `@引用样例.rs#L2-L4`。
6. `surface.read` 从真实 ConPTY 缓冲读取到全部五个预期引用，证明结果不是只存在于 UI 或测试模型中。
7. PowerShell 提示符总计只出现 1 次，所有引用后均未追加回车，未执行任何命令。
8. 默认工作区保持 Common，测试工作区保持 Claude；关闭并重新启动应用后两个选择均正确恢复。
9. 未知持久化枚举值通过单元测试回退 Common，旧会话缺少字段时同样使用 Common。

## 结论边界

- `#L起-L止` 是本产品提供给模型识别的 1-based 闭区间语义，不宣称为各 CLI 官方协议。
- 第一版只允许用户显式选择格式，不探测终端前台程序，也不接管 CLI 的账号、Hook、MCP 或会话协议。
- 本次验收不要求登录 Codex CLI 或 Claude Code CLI；各 CLI 的真实模型端到端识别留在 P2 发布验收。
