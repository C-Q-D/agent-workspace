## 失败与根因记录

第一次直接复用旧门禁时失败于“IPC 在 30 秒内未就绪”。根因是
`scripts/运行Windows终端矩阵验收.ps1` 仍连接旧 `paneflow` 命名管道，并使用旧
AppData Paneflow 数据路径和固定 `paneflow` 进程名；当前 Release IPC 已迁移到
`agent-workspace` 命名空间。该问题已作为 `E002-F01` 修复。

第二次使用普通 Release 二进制运行真实矩阵时，脚本已越过 IPC 就绪点，但失败于缺少
`terminal-perf-metrics` 指标字段。历史性能门禁本来就要求带该 feature 的实验 Release
构建；后续按该前置条件重新构建并通过 1、9、16 三档容量门禁。
