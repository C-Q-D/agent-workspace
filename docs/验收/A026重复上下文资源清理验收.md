# A026 重复上下文资源清理验收

## 结论

A026 已完成。`WindowSession` 继续作为稳定工作区身份与根目录的唯一所有者，
`DisplayState` 决定当前是否存在活动上下文；应用不再按工作区数量常驻 Git watcher，
也不再用 30 秒回退任务遍历全部仓库。

真实 16 窗格验收确认：

- Grid：0 个活动上下文、0 个 Git watcher、0 个文件 watcher、0 个 Review host。
- Focused A/B：始终只有 1 个活动上下文、1 个 Git watcher、1 个文件 watcher。
- Review：始终只有 1 个活动上下文；通用 Git/文件 watcher 均为 0，仅保留 1 个专用
  Review host，避免同一仓库重复监听。
- 16 个真实 PowerShell/ConPTY PID 在 Grid、两次聚焦和 Review 之间全部保持稳定。
- 应用正常退出后没有遗留受测进程。

## 根因与修正

### 旧行为根因

旧实现维护 `git_watch_counts: HashMap<PathBuf, usize>`。每个工作区完成 Git 准备时都会
登记 `.git` watcher；30 秒回退任务也会遍历全部工作区并执行 Git 探测。因此 16 窗格
矩阵即使没有聚焦上下文，仍会产生 16-root 后台工作。

文件侧边栏与 Diff Review 原本已经按可见生命周期创建和释放资源，真正的重复所有权位于
应用级 Git watcher 和全工作区回退任务，而不是文件树本身。

### 修正后的所有权

- 应用仅保存 `active_git_watch: Option<PathBuf>`。
- watcher 目标从 `DisplayState` 的稳定工作区 ID 查找 `WindowSession` 后派生。
- Grid、Settings 和 Review 都释放通用 Git watcher；普通 Focused 态最多登记一个。
- Review 使用自身专用 host/watcher，不与应用级 watcher 重叠。
- 工作区关闭、切换、Git 准备完成和展示状态转换均通过同一个资源协调入口。
- 30 秒容错刷新只探测当前活动 root；Grid 不执行 Git 探测。
- 新增只读 `workspace.context_resources` 验收接口，仅报告资源数量，不读取终端、文件或
  Git 内容。

## 红灯与回归

先新增契约测试
`grid_must_not_start_per_workspace_git_context_resources`。旧实现因缺少单活动 watcher
字段并保留全工作区 watcher/轮询而失败；完成所有权迁移后通过。

最终代码门禁：

```text
cargo test -p paneflow-app grid_must_not_start_per_workspace_git_context_resources
1 passed

cargo test -p paneflow-config

cargo test -p paneflow-app
1486 passed，0 ignored

cargo test -p paneflow-app --test flex_nchild
5 passed

cargo fmt --all -- --check
```

静态复核确认生产代码中不存在 `git_watch_counts`，Git 回退刷新不再遍历
`app.workspaces`，工作区 Git 准备完成也不再无条件登记 watcher。

## 验收脚本问题记录

活动上下文脚本首次执行时错误设置了不存在的 `PANEFLOW_IPC_SOCKET`，应用实际读取
`PANEFLOW_SOCKET_PATH`，因此客户端连接了错误管道并超时。该现象不是产品死锁。确认环境
变量边界后仅修正脚本并重新执行；失败夹具、过期证据和状态备份均已按精确路径清理。
