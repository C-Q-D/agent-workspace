# A021 会话身份与所有权契约验收

## 结论

A021 已用可重复测试固定 WindowSession 后续收敛必须维持的行为边界，本原子没有修改
生产代码：

- 创建入口把稳定工作区 ID 与稳定 `workspaceRoot` 成对保存，列表索引不能替代身份。
- Focused、Review、Settings 只是同一会话的视图，切换视图不改变 ID、root 或已绑定
  的终端 Surface。
- 从工作区 A 切换到 B 时只保留 B 的活动上下文，并释放 A 的终端 Surface 绑定。
- 关闭最后一个工作区后，活动 ID、root、Surface 和展示上下文全部清空。
- 会话恢复只接受原来仍存在的目录，不回退到进程当前目录。
- 非 Git 目录通过真实 `git init` 初始化；重复准备复用同一个仓库。

## 当前缺口红灯

两条测试使用 `#[ignore]` 保存后续目标态，普通 CI 不执行；显式执行时均稳定失败：

1. A022 红灯：生产代码尚无统一持有会话 ID、稳定 root 与终端生命周期的
   `WindowSession` 聚合对象。
2. A024 红灯：`FocusedWorkspaceContext` 仍保存第二份 `workspace_root`，活动文件/Git
   上下文尚未完全从聚焦会话派生。

A022 与 A024 完成时必须把源码检查替换为真实类型/API 断言并移除对应忽略标记。

## 测试结果

```text

paneflow-config                       113 passed
paneflow-app                         1476 passed, 2 ignored
flex_nchild                              5 passed
cargo fmt --all -- --check               passed
git diff --check                         passed
```

首轮真实 Git 契约测试曾因 Windows 规范化路径带 `\\?\` 前缀而失败。Git 初始化与复用
已经成功，第一次偏离发生在测试把规范化返回值与非规范化临时目录直接比较。修正只让
期望值走同一 `canonicalize` 规则，仍严格比较完整目录身份，没有放宽生产行为。

## 可重复命令

```powershell
cargo test -p paneflow-app window_session_contract --quiet --locked
cargo test -p paneflow-app window_session_contract --quiet --locked -- --ignored
cargo test -p paneflow-config --quiet --locked
cargo test -p paneflow-app --quiet --locked
cargo test -p paneflow-app --test flex_nchild --quiet --locked
cargo fmt --all -- --check
```

第二条命令当前必须以两条上述目标态失败退出；若它意外通过但测试仍有 `#[ignore]`，
应先检查契约是否已经被实现，再由对应迁移原子移除忽略标记。

## 范围边界

A021 没有创建新 manager、没有改变 PTY、Git watcher、文件树或展示状态，也没有增加
轮询。A022 才引入最小会话聚合根；A024 才移除活动上下文中的重复 root。
