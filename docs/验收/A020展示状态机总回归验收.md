# A020 展示状态机总回归验收

## 验收结论

V1-04 展示状态机统一已经完成：

- `PaneFlowApp` 不再保存平行的 `mode` 或 `settings_section` 字段。
- `DisplayState` 是 Grid、Focused、Review、Settings 及其返回状态的唯一事实源。
- 所有展示转换统一经过 `DisplayCommand`，渲染和动作直接读取同一个状态对象。
- `WorkspaceFocusState` 迁移别名、`legacy_mode` 投影和转换后的双写桥均已删除。
- 旧 Agents 渲染分支和标题栏动作注册已从当前产品主路径断开；其源码按 A014 决策
  暂时隔离，A027 再处理公开产品面与默认编译边界。
- 历史 `SessionState.mode` 仍可反序列化，但 `skip_serializing` 保证新会话不再写出；
  bootstrap 只在加载边界读取一次并归一化为安全 Grid。

## 验收脚本身份修正

专用会话恢复脚本仍使用旧 `paneflow` 管道、AppData 路径和进程名。该偏离与 A019
首次 Review 验收已确认的根因完全相同，可由源码静态定位，不是本次状态机失败。

因此没有修改生产逻辑、增加等待或放宽断言，只把脚本迁移到：

- `%USERPROFILE%\.agent-workspace`
- 独立 `agent-workspace-session-*` 命名管道
- `agent-workspace` 进程身份

修正后 20 工作区真实恢复一次通过。

Rosetta 等 Paneflow 产品面按 A027～A032 的既定顺序处理。
