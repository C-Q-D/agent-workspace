# P1.5 16GB 容量回归验收报告

## 结论

1、9、16 个真实 Windows PowerShell/ConPTY 的 30 秒容量回归全部通过。16 终端时，桌面应用主进程峰值 Working Set 为 236.230 MiB，约占 16 GiB 的 1.44%，低于 256 MiB 门禁。该结果来自默认终端历史由 10,000 行收紧到 4,000 行后的最终 Release 二进制。

## 验收产物

- 代码提交：`83d3f9952fbd3d88c04cc2504250f9222645fc64`
- 二进制 SHA-256：`8FAA6BBEE2D0EB5E957795335358248DDA87C01F0BF5E9D287C1AD51B0A856B1`
- 构建：Release + `terminal-perf-metrics`
- 负载：每个窗口一个真实终端 shell，再启动一个真实 PowerShell 持续输出进程；每 250 ms 输出一条记录。
- 采样：每个容量点连续 30 秒，随后等待最终标记、执行 32 次真实窗口切换并正常关闭。

## 重绘与实际体验

- 9 终端档：聚焦终端的输出变化触发立即重绘；后台终端的同类变化全部由重绘门控抑制。
- 16 终端档：聚焦终端 172 次变化触发立即重绘；后台终端 173 次变化全部被抑制。
- 16 窗口矩阵截图中所有终端持续更新；单窗口放大后左侧窗口列表和右侧文件树保持可用。
- 32 次循环切换前后 PowerShell PID 集合不变，说明切换不会重启终端。

## 与 16GB 用户约束的关系

桌面应用本身在 16 终端下约占 16 GiB 的 1.44%。本轮完整进程树峰值约 3.46 GiB，其中测试用的 32 个 PowerShell 进程约占 3.10 GiB，明确显示主要成本来自每个窗口内的真实进程，而不是桌面外壳。

真实 Codex CLI、Claude Code CLI、MCP 服务和项目构建可能比 PowerShell 测试负载更占内存，因此本报告不承诺 16GB 机器适合同时运行 16 个重型模型任务。产品需要保持窗口数量动态，并让用户按任务重量选择并发数；本门禁保证桌面外壳不会额外占用数 GiB 内存。
