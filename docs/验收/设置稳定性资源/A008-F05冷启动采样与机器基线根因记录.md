# A008-F05 冷启动采样与机器基线根因记录

## 最小复现

A008 第三次真实运行生成通过结果，但代码执行顺序为：

```text
Start-Process → Wait-AppReady → Measure-ResourcePhase(cold-start)
```

因此名为 `cold-start` 的十个样本全部发生在主窗口与生产 IPC 已经就绪之后。结果 JSON
同时没有 Windows 版本、物理内存、处理器和逻辑处理器数量。

## 实际值、期望值与首次偏离

- 实际阶段测量的是“启动完成后的零工作区空载”。
- A008 要求记录启动采样峰值；A009 还必须给出可复述的基线机器。
- 第一次偏离发生在场景生命周期排序和结果环境 schema，不是产品资源超标。

## 排除项

- 9/16 两个场景、四阶段各十个样本、设置、聚焦、恢复和零残留全部通过，排除了产品
  生命周期失败。
- 截图只包含 AgentWorkspace，且右侧文件和 Git `+1` 可见，排除了空壳聚焦。
- 16 窗格宿主 Private Memory 采样峰值 222.258 MiB；稳定空闲宿主 CPU 约 0.43%，
  未观察到持续抖动，但这些数据不能修正阶段命名错误。
- 失败属于验收语义不完整，不能靠 A009 文案补写机器信息。

## 根因修复

- 在 `Start-Process` 返回后立即开始冷启动资源采样，完成后再要求 IPC 就绪。
- 记录“采样在就绪前开始”的机器字段；由于采样期间不做高频 IPC 轮询，只把随后观察
  到的就绪时间写为上界，不冒充精确启动延迟。
- 总结果新增 Windows、物理内存、CPU、逻辑处理器与 PowerShell 版本。
- 保留第三次运行作为失败证据，修复提交后完整重跑 9/16 场景。
