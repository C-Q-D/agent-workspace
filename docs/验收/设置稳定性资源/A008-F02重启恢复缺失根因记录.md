# A008-F02 同场景重启恢复缺失根因记录

## 最小复现

对 A007 提交 `2fe6376` 的 `Invoke-Scenario` 生命周期做静态跟踪：

```text
启动一次 → 创建工作区 → 四阶段采样 → 正常关闭 → 返回结果
```

9 窗格和 16 窗格分别使用不同 USERPROFILE、配置与会话目录，因此两个场景各启动一次
不能证明任何一个场景完成了应用重启恢复。

## 实际值、期望值与首次偏离

- 实际结果只证明每个场景能正常启动和退出。
- A008 要求在同一隔离会话中完成一次正常退出后的应用重启恢复。
- 第一次偏离发生在 A007 场景生命周期设计：把“两个场景的两次启动”误当成“同一场景
  的重启”。

## 排除项

- 两个场景的 USERPROFILE 和会话路径不同，排除了跨场景共享恢复状态。
- 第一轮正常退出已经写入 `sessions/workspaces.json`，恢复输入确实存在。
- 产品既有契约是稳定 workspace ID 恢复、重新创建真实 PTY；不承诺旧 PowerShell PID
  跨应用重启存活。

## 根因修复

每个 9/16 场景第一次正常退出后，使用同一 USERPROFILE、配置、会话和命名管道再次启动：

- 工作区数量和稳定 workspace ID 必须一致；
- Surface 与工作区重新可用；
- PowerShell PID 必须更换，证明新 PTY 已创建；
- 十项设置和未知字段必须恢复；
- 第二次也必须正常退出且完整进程树零残留。

脚本契约测试固定这些结果字段，防止以后再次把独立场景启动误写成重启恢复。
