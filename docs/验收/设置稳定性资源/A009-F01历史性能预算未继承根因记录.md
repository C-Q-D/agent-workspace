# A009-F01 历史性能预算未继承根因记录

## 最小复现

对照当前 A008 结果与既有 P1.5 门禁：

```text
既有持续输出节拍：250 ms/终端
既有宿主 CPU 门禁：≤ 1%
既有宿主 Working Set 门禁：≤ 256 MiB

A007/A008 输出节拍：200 ms/终端
A007/A008 数字门禁：无，只检查生命周期布尔值
```

第三轮与第四轮 200ms 活动输出的宿主 CPU 分别约为 1.16% 和 1.15%。这些结果不能与
250ms 的历史基线直接比较，也不能通过临时把门槛改成 2% 来关闭 P2-05。

## 实际值、期望值与首次偏离

- A007 正确建立四阶段和四类资源 schema，但自行选择了 200ms 输出节拍。
- `运行Windows16GB性能门禁.ps1` 与 P1.5 报告已经固定 250ms、CPU 1%、Working Set
  256 MiB。
- 第一次偏离发生在 A007 工作负载和 summary checks 设计：没有复用历史负载与预算。

## 排除项

- 9/16 工作区、ConPTY、设置、聚焦、恢复、重启和零残留均通过，排除了产品生命周期
  错误。
- 宿主、Shell、CLI 已分组，排除了把 PowerShell CPU 误算为应用 CPU。
- CPU 使用累计处理器时间差、实际样本跨度和逻辑处理器数计算，排除了瞬时任务管理器
  读数。
- 200ms 比 250ms 多 25% 输出事件，足以让负载不可直接比较；不能据此判定真实回归。

## 根因修复

- 默认输出节拍恢复为 250ms，并写入结果 contract 与 budgets。
- 非冷启动阶段的宿主归一化 CPU 必须不高于 1%。
- 所有阶段宿主 Working Set 采样峰值必须不高于 256 MiB。
- 每阶段至少两个样本，避免极端参数让首尾 CPU 差值退化为零。
- 门禁将派生指标和阈值一并写入 JSON；任一失败保留证据并非零退出。

修复后必须完整重跑 9/16 场景，旧 200ms 结果保留为历史证据但不用于关闭 P2-05。
