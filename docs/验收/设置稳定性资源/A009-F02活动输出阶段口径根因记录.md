# A009-F02 活动输出阶段口径根因记录

## 最小复现

修复 A009-F01 后的真实数值门禁运行：

| 窗格 | 阶段 | 宿主 CPU | 1% 门禁 |
|---:|---|---:|---|
| 9 | 活动输出 | 1.2955% | 失败 |
| 16 | 活动输出 | 1.0846% | 失败 |

其他非冷启动阶段 CPU、全部 Working Set、样本数、设置、生命周期、重启和零残留均通过。

## 实际值、期望值与首次偏离

- P1.5 的 250ms 持续输出测试先进入单窗口聚焦，再采样一个可见终端与后台隐藏终端。
- A007/A008 的活动输出发生在矩阵总览，9 或 16 个终端都可见；文件/Git 聚焦安排在输出
  完成后的下一阶段。
- A009-F01 把历史聚焦态 1% 阈值应用到全可见矩阵输出，阶段语义不一致。
- 第一次偏离发生在场景动作排序，不在 CPU 计算或性能阈值。

## 排除项

- CPU 使用宿主累计处理器时间、实际首尾跨度和 20 个逻辑处理器归一化，排除了瞬时读数。
- Shell 与 CLI 单独分组，排除了子进程 CPU 归入宿主。
- 9/16 稳定空闲分别为 0.3389%/0.4427%，文件/Git 聚焦为
  0.3554%/0.3018%，排除了持续后台抖动。
- Working Set 峰值最高 192.008 MiB，低于 256 MiB。
- 历史脚本源码明确在采样前调用应用级放大，不能用“同样是持续输出”忽略可见性差异。

## 根因修复

场景顺序改为：

```text
稳定空闲 → 应用级聚焦 → 全部终端持续输出并采样 → 文件/Git 聚焦采样 → 主动恢复
```

这样活动输出继续验证所有真实后台终端输出完整，同时复用隐藏重绘门控与历史 1% CPU
口径。门槛保持 1%，不增加等待、不减少终端、不降低输出频率；失败结果和日志完整保留。
