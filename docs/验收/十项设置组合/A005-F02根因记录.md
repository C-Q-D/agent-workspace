# A005-F02 根因记录

## 失败现象

A005 第二次真实运行已通过工作区稳定身份采集，并在 AgentWorkspace 设置页完成 General
页面的 Shell、引用格式、Git 策略和矩阵密度修改。进入 Themes 页面后，按第一轮目标先
选择 Dark，再选择 Claude 预设，磁盘结果变为：

```json
{
  "theme": "Claude"
}
```

`theme_mode` 被生产设置页删除，因此脚本等待的
`theme_mode = "dark"` 与 `theme = "Claude"` 永远不会同时出现。

## 根因

A004 把主题模式和主题预设误当成可自由组合的两个控件。实际产品契约是：

- 选择 Light、Dark 或 System 时，`persist_theme_selection` 同时写入模式和该模式解析
  得到的默认主题。
- 选择 Vercel、Claude 或 Cursor 预设时，`persist_theme_preset_selection` 主动删除
  `theme_mode`，只保留预设 `theme`。

因此 `dark + Claude` 和 `light + Cursor` 都是设置页不可达状态。验收器的目标数据错误，
产品行为符合当前设计。

## 修复与验证边界

两轮目标改为设置页真实可达且仍能覆盖两个磁盘键的组合：

- 第一轮：`theme_mode = "dark"`，`theme = "One Dark"`。
- 第二轮：`theme_mode = "light"`，`theme = "AgentWorkspace Light"`。

脚本契约测试增加精确断言。修复不修改主题设置实现，不手工补写 JSON，也不把本次未完成
运行记为通过。
