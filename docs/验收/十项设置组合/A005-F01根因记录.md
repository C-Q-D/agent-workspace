# A005-F01 根因记录

## 失败现象

2026-07-25 首次执行 `scripts/运行Windows十项设置组合验收.ps1` 时，真实 Release
应用已创建一个工作区、一个 Surface 和一个 PowerShell/ConPTY。验收器在读取第一份
生命周期快照时失败：

```text
The property 'id' cannot be found on this object.
```

失败发生在任何设置页修改之前，因此两轮设置结果没有产生，也不能被记为通过。

## 最小复现与第一次偏离

最小复现是对生产 `workspace.list` 响应执行
`$Workspaces | ForEach-Object { $_.id }`。源码
`src-app/src/app/ipc_handler.rs` 的 `workspace.list` 投影只公开 `index`、`title`、
`cwd`、`panes`、`terminal_status`、`reference_format` 和 `active`，没有公开
`Workspace.id`。

第一次偏离位于验收器的 `Get-LifecycleSnapshot`：脚本把预期存在的稳定 ID 字段写成
了并不存在的 `id`，严格模式立即报错。

## 根因与排除证据

根因是 IPC 可观测性契约缺少稳定工作区 ID，同时验收器错误假设字段存在。它不是配置
解析、设置写入、watcher、PTY 创建或路径隔离问题：

- `workspace.create` 已成功，生产 `workspace.list` 返回一个有效工作区。
- `surface.list` 和真实 PowerShell 已经就绪。
- 错误在设置页第一轮目标等待之前发生。
- `Workspace` 内部确实拥有创建时分配的 `u64 id`，只是列表投影没有序列化它。

## 修复位置

修复在根因边界完成：

1. `workspace.list` 增加向后兼容的只读字段 `workspace_id`，继续保留可能随列表变化的
   `index`。
2. 用纯投影测试证明 `workspace_id` 与 `index` 是两个不同语义。
3. 验收器读取 `workspace_id`。
4. 失败清理记录并回收完整应用进程树，避免真实验收异常退出后遗留 PowerShell。

本修复不改变设置值、设置生命周期、工作区导航或 PTY 行为。
