# UNIT-34 用户数据布局契约验收报告

## 结论

UNIT-34 于 2026-07-19 验收通过。AgentWorkspace 已在 `paneflow-config` 中建立统一的 `UserDataLayout`，发布构建固定使用 `%USERPROFILE%\.agent-workspace`，调试构建固定使用 `%USERPROFILE%\.agent-workspace-dev`。配置、会话、状态、稳定 helper、可重建缓存和诊断日志均由同一布局对象给出路径，既有配置、会话与 Markdown 缓存入口保持兼容。

真实文件系统测试在隔离用户主目录中创建全部六类顶层目录和旧 Paneflow 数据哨兵，仅删除布局明确标记为 rebuildable 的 `cache/`。删除后，设置、工作区会话、遥测标识、稳定 helper、更新日志和旧数据哨兵均存在且字节不变。完整配置层与主程序回归全部通过，测试后无 AgentWorkspace 进程残留。

机器可读结果见 [用户数据布局契约运行结果](用户数据布局契约数据/Release-20260719-192127/运行结果.json)。

## 目录契约

| 目录 | 生命周期分类 | 当前职责 | 清理与保留规则 |
| --- | --- | --- | --- |
| `config/` | durable | 用户设置 | 备份、升级和卸载边界必须保留 |
| `sessions/` | durable | 工作区与会话恢复信息 | 备份、升级和卸载边界必须保留 |
| `state/` | durable | 设备或应用状态，例如遥测标识 | 备份、升级和卸载边界必须保留 |
| `bin/` | durable | 外部 CLI 配置稳定引用的 helper | 即使可重新释放，也不得随普通缓存删除 |
| `cache/` | rebuildable | Markdown 状态和后续可重建运行缓存 | 可整体删除，由应用按需重建 |
| `logs/` | diagnostic | 更新与诊断日志 | 独立保留或清理，不混入普通缓存 |

六个顶层目录在布局测试中互不重叠，并且每个目录只属于一个生命周期分类。布局对象只负责纯路径计算，不在构造时创建目录或写入文件。

## 当前边界

- UNIT-34 不迁移现有生产调用方，因此遥测标识、通知图标、Shell 集成和 Windows 更新文件仍可能使用旧位置。
- 本项目不会迁移、删除或修改 Paneflow 旧数据目录；旧数据只作为越界保护哨兵参与验收。
- `bin/` 被定义为 durable 是为了保持 Codex CLI、Claude Code CLI 等外部配置中的 helper 路径稳定，不代表其中二进制不可重新生成。
- 本单元不增加高频文件日志，避免引入额外磁盘与 CPU 开销。
