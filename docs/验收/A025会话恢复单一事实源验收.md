# A025 会话恢复单一事实源验收

## 结论

A025 已把 `~/.agent-workspace/sessions/workspaces.json` 升级为 metadata-only v2：

- 每个窗口持久化稳定非零 `id`、`workspaceRoot`、标题、布局、矩阵页码、活动项、
  自定义按钮、文件展开状态和引用格式。
- v1 会话可直接迁移到 v2；缺失或重复 ID 在加载边界按磁盘顺序修复，合法 ID 保持。
- 相同 `workspaceRoot` 可以对应多个不同窗口 ID，符合一个仓库同时运行多个 CLI 的场景。
- 终端 scrollback 和最后检测 Agent 标签只兼容读取，不再写入 v2，也不会在重启后恢复。
- 重启始终创建新的 PowerShell/ConPTY；不序列化 PID、进程句柄或终端实体。
- 缺失目录只跳过对应窗口，不替换成进程启动目录；活动索引映射到保留下来的原条目。
- 恢复 ID 会推进运行时计数器，之后新建窗口不会复用已存在 ID。

## 红灯与根因

修改前两条目标测试稳定失败：

```text
session_schema_version_marks_metadata_only_contract
left: 1, right: 2

terminal_runtime_state_is_read_only_legacy_input
JSON 仍包含 scrollback 与 agent
```

根因是 v1 把可恢复元数据与终端运行快照放在同一 schema：窗口 ID 没有落盘，保存过程
还会提取终端缓冲，恢复时则展示已退出进程的 last-known Agent 标签。修复作用在 schema、
加载迁移和保存入口，没有通过清空证据或降低断言绕过问题。

覆盖的新旧 schema 行为包括：

- 重复 root 不去重，多窗格布局叶节点数不变。
- 缺失目录与普通文件拒绝恢复，损坏 JSON 和未来未知版本继续进入既有损坏恢复路径。

## 真实 20 窗口重启

证据：

```text
docs/验收/会话恢复数据/真实重启-20260725-141414/运行结果.json
```

最终 Release 创建 20 个真实 PowerShell/ConPTY 窗口并切换到矩阵第二页：

- 首次退出与重启退出的 schema 都为 v2。
- 两份会话的窗口 ID 都严格为 `1..20`，顺序和映射完全相同。
- 活动项均为索引 19，矩阵页码均为零基第 1 页。
- 两份 JSON 均不包含 `scrollback` 或 `agent` 字段。
- 重启后的 20 个 PowerShell PID 与首次运行全部不同，证明重建而非伪恢复。
- 两轮关闭后的 AgentWorkspace、PowerShell 与 conhost 均零残留。

已人工核对 `重启恢复第二页.png`：界面显示恢复后的第二页、对应窗口标题和 6 个真实
终端窗格。终端中的 `oh-my-posh` 报错来自本机 PowerShell profile 缺少外部命令，
不影响会话、目录、PTY 或进程退出验收。

## 真实 v1 迁移与缺失目录

证据：

```text
docs/验收/工作区恢复生命周期数据/真实恢复-20260725-141438/运行结果.json
```

脚本写入包含“已有 Git、失效目录、非 Git”的 v1 会话后两次启动最终 Release：

- 只恢复两个有效目录，活动项仍映射到原“非 Git”条目。
- v1 第一次退出即升级为 v2，稳定 ID `{1,3}` 在第二次重启后保持。
- 非 Git 目录只执行本地 `git init`，没有 remote；已有仓库的 remote 原样保留。
- 进程启动目录未创建 `.git`，失效目录未被应用创建。
- 两轮真实进程树关闭后零残留，夹具目录已删除。
