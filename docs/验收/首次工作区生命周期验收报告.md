# 首次工作区生命周期验收报告

## 结论

UNIT-21 已通过真实 Windows 验收。应用在没有可恢复会话时保持零工作区和零 PTY，只有用户明确选定目录后才创建首个终端；取消系统目录选择后继续停留在空状态。首个与后续工作区复用同一创建生命周期，非 Git 目录会初始化本地仓库，正常重启恢复稳定目录，损坏会话降级为空工作区。

用于验收的 Release 二进制基于生产提交 `17ce26ba3a656e0abe1b5eff8422648194c481af`，SHA-256 为 `0350A6878082C26AA00440F1EFBE7C8C05A3BF3CF4ECA5914E984DA1C05ED135`。验收脚本与证据在本报告完成后作为独立原子提交保存，因此证据内记录的是被测生产提交，而不是报告提交。

## 独立已知问题

真实 `paneflow new --cwd <DIR>` 已能成功请求服务端创建工作区，但客户端进程随后在 Windows 以 `0xC0000409` 退出。该现象在本轮共享创建编排之前的 Release 二进制上也能复现，因此不是 UNIT-21 引入的回归；缺失 `--cwd` 的参数校验仍能按预期以退出码 2 结束。本报告不把该旧问题混入首次工作区生命周期改动，后续应以独立诊断原子定位客户端退出阶段的根因。
