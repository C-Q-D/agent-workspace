# P1.5 16GB 性能长稳验收报告

## 结论

9 个真实 Windows PowerShell/ConPTY 在每终端 250 ms 持续输出、连续 1800 秒的长稳验收通过。应用峰值 Working Set 为 246.508 MiB，平均 CPU 为 0.4751%，最后两个五分钟 Private 均值分别为 240.958 MiB 与 240.948 MiB，尾段增长为 -0.011 MiB。终端输出完整、后台重绘门控有效、切换稳定，关闭后零残留。

- 构建：Release + `terminal-perf-metrics`

## 内存问题与修复闭环

第一次 250 ms 长稳真实运行中，应用 Private 的最后两个五分钟均值仍增长 14.817 MiB，峰值 Working Set 达 285.414 MiB。线程、句柄、PowerShell PID 和输出均稳定，增长来自仍在填充的 10,000 行终端历史，而持久化和 `surface.read` 实际只保留或读取 4,000 行。

产品修复将默认终端历史收紧为 4,000 行，使实时内存预算与恢复、读取边界一致；用户显式配置仍可在 100～100,000 行内调整。修复后的曲线在填充期分三次扩容，约 15 分钟后稳定在 241 MiB Private 左右，并保持到 30 分钟结束。

## 进程树诊断

完整子进程树的常态为 28 个进程。1800 个样本中有 1797 个保持常态，3 个样本短暂出现 29 或 30 个 Windows 辅助子进程，因此“整棵树 PID 集合每秒绝对不变”为假。

这不代表 PTY 重启：18 个 PowerShell 进程在全部样本中数量恒定，采样前后完整端点 PID 集合一致，64 次切换前后 PowerShell PID 集合一致，9 个终端全部读到最终标记并正常退出。门禁因此以终端 shell 数量、端点 PID、切换 PID、输出完整和零残留为硬条件，同时继续记录整树瞬态作为诊断事实。

## 重绘和实际体验

- 聚焦终端累计 10,200 次变化均触发立即重绘。
- 后台终端累计 10,201 次变化均被隐藏面重绘门控抑制，没有转化为立即重绘。
- 64 次单窗格切换 P95 为 65.529 ms，切换不会重启终端。
- 9 窗格矩阵、单窗格放大、左侧窗口列表与右侧文件树均在真实截图中正常显示。

## 适用边界

本验收证明桌面外壳在 16GB Windows 机器目标下不会因终端历史无限增长而持续吞噬内存，也证明后台终端输出不会引发等量 GUI 重绘。真实 Codex CLI、Claude Code CLI、MCP 服务和项目构建的内存成本仍由各自进程决定；产品不会把 16 个重型 Agent 同时运行解释为 16GB 机器的推荐用法。
