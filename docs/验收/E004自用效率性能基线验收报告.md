## 本原子实际修复的脚本问题

E004 首次真实运行暴露了两个验收脚本问题，均已先定位根因再修复：

1. `运行Windows活动上下文性能验收.ps1` 在 Windows PowerShell 严格模式下对空
   PowerShell/conhost 集合读取 `Measure-Object` 的 `.Sum` 会失败。已改为显式累加函数，
   空集合返回 0。
2. `运行Windows自用效率基线.ps1` 最初使用 Windows PowerShell 启动子脚本，旧矩阵脚本依赖
   PowerShell 7 的 `Get-Process.Parent` 枚举进程树，导致只统计到主进程。已改为使用 `pwsh`
   启动子验收脚本，与既有 16GB 门禁一致。

同时，活动上下文脚本从只支持 2～20 个工作区调整为支持 1～20 个工作区；当只有 1 个工作区
时跳过 A→B 聚焦替换检查，但仍验证 Grid、Focused 和 Review 三阶段资源。

## 后续使用方式

- 后续阶段需要对比资源时，继续运行 `scripts\运行Windows自用效率基线.ps1`。
- `WorkspaceCount` 支持 `1`、`9`、`16`，可用于单窗口、常用多任务和高密度场景。
- 采样器只统计 AgentWorkspace 根进程向下的进程树，外层测试 PowerShell 不计入应用开销。
- 时间戳原始 JSON、Markdown、截图和 CSV 在验收时已生成并通过契约复验；提交前已清理，
  避免仓库被原始性能数据膨胀。需要复核时直接重跑本节命令重新生成。
