# A018 核心聚焦路径迁移验收

## 验收结论

A018 已将矩阵放大、主动恢复、左侧工作区切换、工作区关闭清理、主区域渲染和
文件栏可见性迁移到 A017 的集中展示状态命令。真实 Windows Release 验收通过：

- 9 个和 16 个真实 PowerShell/ConPTY 工作区均完整创建。
- 聚焦后保持单窗口展示，只有脚本主动点击恢复按钮才返回矩阵。
- 聚焦、恢复、配置变更和应用内工作区切换没有改变 Surface ID 或 PowerShell PID。
- 每个终端持续输出均到达完成标记，聚焦文件/Git 上下文来自当前稳定目录。
- 同一会话重启后工作区 ID 恢复，PTY 按预期重新创建。
- 两轮应用均正常退出，实验进程树零残留。
- 10 秒校准采样下宿主 CPU 峰值阶段平均值为 0.7967%，工作集峰值为
  192.109 MiB，仍满足 1% 和 256 MiB 门禁。

通过证据：

```text
docs/验收/设置稳定性资源数据/Release-20260725-120252/门禁结果.json
```

两张 `聚焦文件Git上下文.png` 均由验收脚本直接截取 AgentWorkspace 窗口本身，
分别对应 9 窗格和 16 窗格场景。

## 首次失败与根因

首次运行使用了人工缩短的 `-PhaseDurationSeconds 5`，结果目录为：

```text
docs/验收/设置稳定性资源数据/Release-20260725-120130/门禁结果.json
```

该运行中所有 A018 相关交互、上下文、Surface/PID 稳定、重启和零残留检查均为
`true`。唯一失败项是 `hostCpuWithinOnePercent`：9/16 窗格活动输出阶段平均值分别
为 1.0583% 和 1.2891%。第一次偏离发生在执行参数，因为脚本与既有性能基线的默认
校准窗口是 10 秒，5 秒样本放大了启动活动输出的短时占比。

根因确认后没有修改生产代码、阈值或断言。复验恢复默认 10 秒窗口，保持相同
1% CPU、256 MiB 工作集阈值及 250 ms 输出负载，最终全部通过。失败证据保留，
避免把错误执行参数造成的红灯从历史中抹除。
