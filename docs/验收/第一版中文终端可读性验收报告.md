# 第一版中文终端可读性验收报告

## 验收结论

UNIT19 已通过真实 Windows 验收。修复后，中英文混排、连续中文、中文路径和全角标点均可正确回读，并在 14pt、17pt、21pt 三档终端字号下保持网格列对齐，没有出现宽字符后的字符挤压或覆盖。

## 根因与修复

- Alacritty 使用一个基础单元格和一个 `WIDE_CHAR_SPACER` 表示双列中文字符。
- 原实现虽然跳过占位单元格，却仍把连续中文和后续英文合并成同一个 GPUI 固定列宽塑形批次。
- GPUI 的固定列宽塑形按“基础字形数量”逐列推进，不知道单个中文基础字形占两列，因此宽字符后的字形会落到错误列。
- 修复方式是在宽字符结束后强制重开文本批次，使下一个字形从 Alacritty 的真实网格列重新定位；普通英文字符仍保持连续批处理，避免无关性能退化。

## 验收边界

本机只有 96 DPI，因此本轮没有伪装成 125% 或 150% 操作系统 DPI 验收。17pt、21pt 用于验证字体度量变化下的布局稳定性；真正的多显示器高 DPI 切换仍需以后在相应硬件环境补充。启动终端中出现的 `oh-my-posh` 缺失信息来自当前用户 PowerShell 配置，与中文宽字符渲染无关。
