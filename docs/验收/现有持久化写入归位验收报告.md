# UNIT-35 现有持久化写入归位验收报告

## 结论

UNIT-35 于 2026-07-19 验收通过。AgentWorkspace 当前 Windows 产品范围内的自有持久化写入已经统一归入 `%USERPROFILE%\.agent-workspace`；调试构建使用隔离的 `%USERPROFILE%\.agent-workspace-dev`。遥测标识、通知图标、Shell 集成脚本、版本化 helper、Markdown 阅读状态、Windows 更新暂存与更新日志均直接通过 `UserDataLayout` 取得路径，不再由业务模块拼接系统缓存、系统临时目录或 Paneflow 旧命名空间。

稳定 MCP 与 AI Hook helper 位于 durable `bin/`；可重建内容位于 `cache/`；更新诊断日志位于 `logs/update/`。真实文件系统测试确认整体删除 `cache/` 后，配置、会话、状态、稳定 helper 和诊断日志保持不变，同时缓存目录可以按需重新创建。

机器可读结果见 [现有持久化写入归位运行结果](现有持久化写入归位数据/Release-20260719-194220/运行结果.json)。

## 生产写入归属

| 数据或资产 | 统一位置 | 生命周期 | 生产入口 |
| --- | --- | --- | --- |
| 用户设置 | `config/settings.json` | durable | `settings_path()` |
| 工作区会话 | `sessions/workspaces.json` | durable | `workspaces_path()` |
| 遥测标识 | `state/telemetry_id` | durable | `telemetry_id_path()` |
| MCP bridge | `bin/paneflow-mcp.exe` | durable | `bin_dir()` |
| AI Hook callback | `bin/paneflow-ai-hook.exe` | durable | `bin_dir()` |
| Markdown 阅读状态 | `cache/markdown_state.json` | rebuildable | `markdown_state_path()` |
| 通知图标 | `cache/icons/agent-workspace-notification.png` | rebuildable | `notification_icon_path()` |
| Shell 集成脚本 | `cache/shell/` | rebuildable | `shell_integration_dir()` |
| 版本化 helper | `cache/bin/<version>/` | rebuildable | `helper_cache_dir()` |
| Windows 更新暂存 | `cache/update/` | rebuildable | `update_cache_dir()` |
| Windows 更新日志 | `logs/update/` | diagnostic | `update_logs_dir()` |

稳定 helper 与版本化 helper 被刻意分开：外部 Codex CLI、Claude Code CLI 配置可能长期引用 `bin/` 中的绝对路径，因此普通缓存清理不得删除它们；PTY 每次启动都会重新解析的 wrapper 可安全放入版本化缓存。

## 联合缓存清理验收

验收使用真实临时用户目录和真实文件，不使用内存替身模拟文件生命周期：

1. 在六类目录中创建配置、工作区会话、遥测标识、稳定 helper、Markdown 缓存和更新日志。
2. 在 AgentWorkspace 根之外创建 Paneflow 旧数据哨兵。
3. 依据 `rebuildable_directories()` 真实删除完整 `cache/`。
4. 逐字节核对 durable、diagnostic 和旧数据哨兵。
5. 重新执行通知图标、Shell 集成和 Windows 更新目录准备测试，确认缓存可重建。

## 防回退审计

桌面应用新增源码级门禁，要求遥测、通知、Shell、Windows 更新、Markdown 和 helper 模块保留对应的布局方法调用，并禁止 Windows 更新生产实现重新使用 `std::env::temp_dir()`。稳定 helper 另有纯路径测试，确认它们只能位于 `bin/`，不能落入 `cache/`。

人工生产源码审计未发现 Windows 更新实现中的 `std::env::temp_dir`、`paneflow-update`、`paneflow-msi` 或 `Reinstall PaneFlow` 写入路径。测试源码仍保留对 `paneflow-update` 的否定断言，用于防止旧名称回归，不属于生产写入。

## 明确排除的写入

- `PANEFLOW_HOOK_LOG` 仅在用户显式设置环境变量时写入用户指定路径；应用默认不创建 Hook 日志，不增加后台高频日志。
- Codex CLI、Claude Code CLI 等工具自身的配置和会话目录属于外部工具数据；AgentWorkspace 只在用户主动执行集成安装时修改相应配置。
- 工作区源码、Git 仓库和 worktree 属于用户项目数据，不属于 AgentWorkspace 自有数据根。
- IPC 上下文暂存是一次性、带边界控制的进程间传递，不属于持久用户数据。
- Windows 安装目录中的打包 helper 属于应用安装资产，不属于用户数据。
- macOS、Linux、WSL、SSH 不在当前 Windows 开源版本产品范围内，本单元不改造其更新路径。

## 性能影响

本单元只替换路径计算和文件落点，没有新增轮询、常驻线程、定时器或自动日志。`UserDataLayout` 是纯 `PathBuf` 计算；helper 仍使用 SHA256 命中后不重写的幂等快速路径。缓存删除后也只在对应功能首次使用时按需重建，不会在后台持续扫描目录，符合 16 GB 内存设备优先保持低 CPU、低内存占用的约束。
