# 第一版会话恢复验收报告

## 当前结论

截至 2026-07-18，Windows 第一版的工作区顺序、活动工作区、动态矩阵页码和终端进程重建均通过真实重启验收。测试使用 20 个真实 PowerShell/ConPTY 工作区，没有使用 mock 终端或伪造会话数据。

## 验收环境

- 二进制：启用 `terminal-perf-metrics` 的 Release 构建。
- 被测提交：`2b4cc536493a9e3ffd8d0da210944d2f27291277`。
- 二进制 SHA-256：`0013F1C274F8B2E356CEF2D0F57F42C96DB31546F284D51097B8F33BB0779E4A`。
- 工作目录：本地真实 Git 仓库 `agent-workspace/app`。
- 工作区数量：20；默认 1200×800 窗口下矩阵为 4 页，每页 6 个终端。
- 用户状态：脚本暂存并在 `finally` 中恢复真实 `paneflow.json` 和 `session.json`，实验状态不污染日常会话。

## 真实重启结果

1. 空白启动应用，通过生产 `workspace.create` IPC 入口创建到 20 个真实工作区。
2. 通过真实鼠标点击将矩阵从 `1 / 4` 切换到 `2 / 4`，再聚焦最后一个工作区并正常关闭。
3. 首次退出快照保存了 20 个工作区的原有顺序、`active_workspace = 19` 和 `workspace_grid_page = 1`。
4. 使用同一 Release 二进制重新启动后，工作区顺序、绑定目录、活动项和第二页状态全部恢复。
5. 首次启动和恢复启动分别观测到 20 个 PowerShell 子进程；两组 PID 没有交集，证明恢复过程创建了新的 PTY/PowerShell，而不是误认旧残留进程。
6. 两次正常退出后，所跟踪的应用与子进程残留数量都为 0。

## 异常边界结果

- `restored_cwd_helpers_fall_back_for_missing_directories`：通过。持久化目录失效时会回退到可用目录，不阻断应用恢复。
- `malformed_json_returns_corruption_info_and_writes_backup`：通过。损坏的 `session.json` 会产生可识别的损坏信息和备份，而不是导致启动崩溃。

## 结论边界

- 本次证明“窗口与布局元数据恢复、PTY 重新创建”，不承诺在应用退出后继续保活旧 PTY 进程。
- 动态页码会结合当前窗口尺寸夹紧；本次在相同的 1200×800 视口中验证第二页恢复。
- 当前恢复范围不包含任意 CLI 自身的云端对话恢复语义；Codex CLI、Claude Code CLI 是否恢复其内部对话仍由各 CLI 自身负责。
