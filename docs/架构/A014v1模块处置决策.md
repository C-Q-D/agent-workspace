# A014 Windows 开源 v1 模块处置决策

## 决策状态

- 决策类型：Windows 开源 v1 架构边界 ADR。
- 决策依据：A010 公开入口、A011 默认构建依赖、A012 状态所有权、A013 资源生命周期。
- 适用范围：当前 `agent-workspace/app/` 派生仓库。
- 不适用范围：macOS、Linux、WSL、SSH、v1.1 编辑器及更长期产品功能。
- 人工门：Telemetry 最终去留、公开包型、正式版本号与公开发布仍由 A109～A142 决定。

本文的分类是后续原子的执行约束，不等于本原子已经删除代码或改变发行包。每个条目都必须由责任原子实现并独立验证。

## 分类定义

| 分类 | 执行含义 |

| 完全删除 | 不属于产品边界且无必要兼容责任；删除实现、Action、命令、状态、依赖与测试 |

## 决策理由

### 核心必须围绕用户闭环

v1 的闭环只有“终端矩阵 → 聚焦 → 文件引用 → Git Review → 恢复/切换”。凡不直接服务这个闭环，又引入 Agent 协议、编排、后台扫描或大量 helper 的模块，都不能继续进入默认产品路径。

### IPC 保留，编排层删除

IPC 已解决 Windows CLI 正常退出并拥有连接、队列、deadline 上限。它同时支撑脚本化基础控制、诊断以及可能保留的最小 helper，因此保留协议基础设施。`flow`、broadcast submit 和 conductor 权限改变了产品定位，必须从同一入口中剥离。

### Updater 保留准备，包型由人工门确认

更新检查与 Windows MSI relay 是可公开发行产品的正常能力，保留源码并完成 AgentWorkspace 身份修正。A014 不承诺单 EXE，也不替 A111～A112 选择 MSI/ZIP 对外口径。

### Telemetry 只给推荐值

基于本地优先、开源用户信任和默认载荷精简，推荐 v1 默认构建不包含 PostHog。最终是删除、feature 隔离还是默认禁用，由 A109～A110 人工确认；在此前不得把推荐写成用户决定。

### 完全删除项没有兼容价值

Rosetta UI、Composer、Broadcast、Attention Queue、Launch Pad、Conductor/DAG 和 workspace template builder 都不属于“用户在普通 PowerShell 中运行 CLI”的必要协议。旧会话中真正需要兼容的是模式、稳定 workspace 和终端布局，而不是这些 UI 实体。

## 资源与构建约束

1. A015～A026 状态/所有权重构必须处理 A013 的 30 秒全 cwd Git fallback，不得再创建第二套 watcher 或 manager。
2. A027～A038 隔离遗留产品面后，重新生成 A010 入口清单和 A011 构建图；“按钮隐藏”不等于模块退出默认构建。
3. Windows v1 默认构建不得无条件嵌入并在包中重复 17 个 helper。
4. 终端事件消费必须保持事件驱动；高速输出的无界 channel 风险通过后续真实性能门禁验证，不允许靠丢终端输出解决。
5. Config/Theme watcher 的真实进程级生命周期必须由所有者或文档明确，不再声称应用可主动 drop 一个并未持有的 handle。
