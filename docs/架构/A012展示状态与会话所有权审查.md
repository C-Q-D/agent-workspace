# A012 展示状态与会话所有权审查

> 本文主体是 A012 时点的迁移前事实快照。A015～A020 已完成单一展示状态迁移，
> 当前结论与总回归证据见
> [`A020展示状态机总回归验收.md`](../验收/A020展示状态机总回归验收.md)；
> 下文保留用于说明旧双写缺口，不再代表当前实现。

## 审查结论

本原子只记录 A012 时点行为，不引入新状态机。当时应用能通过入口顺序和多处协调函数维持核心流程，但“用户正在看什么”并没有单一事实源：

- `PaneFlowApp.mode` 决定 CLI、Diff、Agents 主模式。
- `settings_section` 作为覆盖层，优先于 `mode` 渲染。
- `WorkspaceFocusState` 决定 CLI 主模式内显示矩阵还是单工作区。
- `active_idx`、`WorkspaceFocusState.workspace_id/workspace_root` 与 `files_tree.root` 分别保存活动工作区、聚焦工作区和文件上下文。
- `SessionState` 保存 `mode` 与 `diff_scope`，但启动时只允许恢复到 CLI；聚焦和文件上下文不持久化。

因此，现有公开入口通常能组成正确状态，但类型系统仍允许不可公开到达、无法完整恢复或表达重复事实的组合。A015～A020 应统一展示状态；A021～A026 应收敛 `WindowSession` 与 `ActiveContext` 所有权。

## 当前读写关系

```text
SessionState
  ├─ active_workspace ───────> PaneFlowApp.active_idx
  ├─ mode ──restored_public_mode()──> PaneFlowApp.mode（仅恢复 CLI）
  └─ diff_scope ─────────────> DiffModeState.diff_scope（即使主模式被降为 CLI）

PaneFlowApp
  ├─ mode ───────────────────> CLI / Diff / Agents 主内容
  ├─ settings_section ───────> Settings 覆盖主内容，渲染优先级最高
  ├─ active_idx ─────────────> 当前 Workspace
  ├─ workspace_focus ────────> 矩阵 / 放大、稳定 ID、稳定 root、终端 Surface
  ├─ files_tree.root ────────> 右侧文件上下文
  └─ diff_mode ──────────────> 当前 Git 审查实体、范围和缓存
```

`WorkspaceLifecycle` 不保存展示状态。它只验证恢复目录、建立稳定注册信息，并在失效条目被过滤后重新映射活动索引。

## 所有权清单

| 用户语义 | 当前主要事实源 | 其他副本或派生状态 | 当前保护方式 |
|---|---|---|---|
| 主内容模式 | `PaneFlowApp.mode` | `SessionState.mode` | 启动时 `restored_public_mode` 把 Diff/Agents 降为 CLI |
| 设置是否可见 | `settings_section` | 无统一 `AppView` 表达 | `main.rs` 首先渲染设置 |
| 活动工作区 | `active_idx` | Session 中的活动索引 | 激活入口统一经过 `begin_workspace_activation` |
| 放大工作区 | `WorkspaceFocusState.focused` | 当前 `Workspace` 的 ID 与 `cwd` | 激活、关闭后由 workspace 操作协调 |
| 稳定目录 | `Workspace.cwd` 与聚焦上下文中的 root | `files_tree.root`、Diff repo root | 重定向和异步结果应用前校验 root |
| 文件引用终端 | 聚焦上下文的 `terminal_surface_id` | 当前窗格选择 | 切换稳定 ID 时清空旧 Surface |
| 矩阵恢复定位 | `reveal_workspace_id` | `workspace_grid_page` | 一次性读取；再次聚焦会取消旧定位 |
| Git 审查上下文 | 活动 Workspace + `diff_mode` | 已缓存 Diff 实体 | 进入 Review 前要求聚焦 ID 等于活动 ID |

## 必验状态转换

| 场景 | 当前转换 | 已有保护或特征测试 | 结论 |
|---|---|---|---|
| 启动恢复 | 载入工作区与活动索引；主模式统一恢复为 CLI；聚焦和文件栏从空状态开始 | `restored_mode_only_allows_cli_to_start_directly`、`workspace_lifecycle::tests` | 可恢复，但保存的非 CLI 模式不是可恢复事实 |
| 网格进入聚焦 | 左栏或放大入口先写稳定 ID/root，再激活对应工作区 | `switching_workspace_replaces_root_and_drops_stale_surface` | 正常入口一致 |
| 聚焦切换 | `begin_workspace_activation` 同时更新 `active_idx` 与聚焦上下文，随后重定向文件/Diff | 同上及 `refocusing_after_restore_cancels_stale_grid_reveal` | 正常入口一致，仍依赖调用顺序 |
| 主动恢复矩阵 | 仅 `restore_workspace_grid` 清除聚焦并生成一次性定位目标，同时关闭文件栏 | `restoring_grid_is_explicit_and_reveal_is_one_shot` | 满足“只有主动缩小才缩小” |
| 进入/退出 Diff | 进入前要求聚焦 ID 等于活动 ID，关闭文件/会话栏；退出回 CLI 并恢复文件上下文 | `focused_review_requires_matching_stable_workspace_id` | 正常入口安全 |
| 进入/退出设置 | 设置作为覆盖层，不改变 `mode` 或聚焦状态；关闭后显露底层状态 | 静态契约脚本覆盖入口与渲染优先级 | 是覆盖语义，但资源和侧栏组合不受类型约束 |
| 关闭聚焦工作区 | 删除后重新钳制活动索引；尚有工作区则重定向聚焦，无工作区则清空聚焦和文件栏 | `clearing_focused_workspace_drops_all_active_context` | 正常入口可自愈 |
| 异常会话恢复 | 失效目录被过滤，活动索引重映射；不可恢复模式降为 CLI | bootstrap 与 lifecycle 特征测试 | 不会伪造聚焦上下文 |

## 可组成的非法或含混状态

1. `settings_section.is_some()` 可与 Diff、Agents、文件栏打开同时存在。设置会覆盖主内容，但底层模式和右侧资源仍可能存活；这是含混的覆盖组合，不是一个统一展示状态。
2. `mode == Diff` 与“没有聚焦工作区”或“聚焦 ID 不等于活动 ID”在字段层面可同时存在。公开进入函数会拒绝它，但字段和会话 schema 没有表达该不变量。
3. `mode == Agents` 仍可渲染和保存，公开入口却已隐藏，启动又将其降为 CLI。它是遗留的可表示但不可公开恢复状态。
4. `active_idx` 指向 A、聚焦上下文指向 B 在转换中可短暂出现；当前依靠 `begin_workspace_activation` 和 `reconcile_maximized_workspace_after_change` 修正，而非由一个对象保证。
5. `Workspace.cwd`、聚焦 root 和 `files_tree.root` 可分别保存目录。异步 generation/root 校验能防止旧结果落入新上下文，但没有消除重复事实。
6. 会话会保存 Diff/Agents `mode`，启动却有意丢弃；`SessionState.mode` 当前不是可靠的恢复事实。
7. `diff_scope` 即使在启动模式被降为 CLI 后仍会恢复为潜伏状态，之后进入 Diff 时可能被入口重置。它不是当前可见状态的直接组成部分。
8. 聚焦上下文不持久化，因此保存 `mode == Diff` 时缺少重建 Diff 前置条件。启动降级是正确防御，但 schema 注释仍声称可直接恢复。

## 重复事实源与过期契约

- `src-app/src/app/session.rs` 仍以“重开原屏幕”解释保存 `mode`，而 bootstrap 的真实行为是只恢复 CLI。
- `crates/paneflow-config/src/schema.rs` 对 `mode` 和 `diff_scope` 的注释仍宣称恢复 Agents/Diff，与实现冲突。
- `AppMode::Agents`、Agents 相关会话数据和公开产品面之间存在遗留边界，需由 A014 给出处置建议、A027～A032 执行公开路径退出。
- 当前没有显式 `ActiveContext` 类型；文件、引用终端和 Diff 的活动上下文散落在聚焦状态、Workspace、文件树和 Diff 实体中。

## 后续原子的约束

- A015～A020 应用一个可枚举的展示状态表达 CLI 网格、CLI 聚焦、Review、Settings 等公开组合，并对旧会话做单向归一化；不得再新增平行布尔字段。
- A021～A026 应让稳定工作区会话成为 ID/root/终端绑定的所有者，让文件与 Git 上下文从同一活动上下文派生；异步结果仍必须保留 generation/root 校验。
- A012 不删除 Agents、不改变会话 schema、不修正文档注释，因为这些分别属于 A014、A015～A020 和后续迁移原子。
