# P1.5 架构与产品体验复查报告

## 结论

UNIT-17～20 均已通过真实 Windows 验收，16GB 性能门禁没有发现阻塞：16 个真实终端时应用 Working Set 峰值为 236.230 MiB，9 终端持续输出 30 分钟后尾部五分钟内存变化为 -0.011 MiB，切换 P95 为 65.529 ms，关闭后零残留。

P1.5 整体暂不宣告无条件完成。复查发现一个主流程入口缺口：首次启动或会话无法恢复时，`bootstrap.rs` 的默认工作区直接使用 `implicit_launch_cwd()`，只启动 Git 状态探测，没有复用用户创建窗口时的目录选择和 Git 准备流程。这与“创建窗口时必须由用户选择或指定稳定 `workspaceRoot`，非 Git 目录自动初始化”的 P0 规则冲突。

建议在进入 P2 前新增 UNIT-21，先由用户确认首次启动交互，再按独立原子实现。推荐方案是空工作区首屏：用户选择目录后才创建终端；取消选择则保持空状态，不隐式绑定当前目录。

## 已解决问题

1. Review 保留左侧窗口列表，可在 A→B→A 之间直接切换审查对象，PTY PID 与后台输出保持稳定。
2. 公开产品面只保留 CLI 与 Review；旧 Agents 会话安全回退 CLI，不启动隐藏 Agents 终端。
3. 真实 ConPTY 的中文、英文和混排字符宽度恢复正确。
4. 默认滚动缓冲从 10,000 行收紧至 4,000 行，1/9/16 容量和 30 分钟长稳门禁通过。
5. 总览、聚焦文件树、Review 与返回 CLI 的主流程在当前 Release 二进制中连贯可用。

## 架构深化候选

### 1. 统一工作区创建生命周期——最高优先级

当前目录选择器、IPC 创建、默认启动和会话恢复的构造顺序不一致。完整生命周期应由一个深模块统一承载：解析或选择根目录、分配稳定 ID、创建 Terminal/Pane、订阅事件、登记 Git 准备、启动 watcher/统计、加入列表、激活并保存会话。

删除测试：如果该模块成立，`default_workspace`、目录选择器和 IPC 中重复的 `TerminalView::with_cwd*`、订阅、Git 统计与保存顺序应显著减少；若只是包一层名称却仍由调用方拼装步骤，则没有深化成功。

### 2. 深化聚焦工作区编排

`WorkspaceFocusState` 已经是正确核心，但聚焦后文件树、Diff、可见性和会话持久化仍由多个调用方协调。后续可让聚焦编排模块输出一次完整、可验证的上下文转换，减少 UI 直接拼接副作用。

### 3. 收窄终端运行时接口

`pty_session.rs` 实现很深但外露字段和调用面仍宽。应按输入、输出快照、生命周期和诊断能力收窄接口，而不是机械拆文件。该工作风险高且不属于首启缺口修复，应单独成原子并配置性能回归门禁。

### 4. 隔离不可达的 Review 外层范围

公开 v1.0 的 Review 只审查当前聚焦仓库，但历史多项目、worktree picker 与 Agents 分支仍保留在外层状态和渲染分支。应保留 `DiffView`，逐批删除或隔离公开路径不可达的外层逻辑；每批必须保持 CLI/Review 往返与会话兼容。

### 5. 集中资源预算语义

滚动缓冲、提取上限、IPC 读取和 MCP 输出目前存在多个数值相同但语义不同的 4,000 行限制。应建立统一的资源策略模块，明确“终端历史”“单次提取”“IPC 响应”“MCP 响应”是不同预算，避免再次出现默认值漂移造成真实内存回归。

## 产品体验结论

详细截图与逐步审查见《P1.5 产品体验复查报告》。当前主流程没有新增交互阻塞；窄屏工具栏密度、约 22 px 的放大按钮、完整键盘/读屏/200% 缩放验证进入 P3。PowerShell profile 错误会原样显示，这符合真实终端边界，但 P2 仍需要环境诊断帮助普通用户区分应用问题与 shell 配置问题。
