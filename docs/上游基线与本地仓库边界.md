## 隔离方式

本地派生仓库使用 `git clone --no-hardlinks` 从只读样本建立，因此拥有独立的 Git 对象存储和工作区。创建后已经移除克隆生成的 `origin`，当前仓库不配置任何 remote。

这意味着：

1. 派生仓库的文件修改和本地提交不会改变 `paneflow/` 工作区。
2. 当前不存在可被误推送的 Paneflow 远端地址。
3. 所有实验提交只保存在本机。
4. 后续正式确定开发时，为 AgentWorkspace 单独配置新的 `origin`；Paneflow 只能作为只读 `upstream` 获取更新。

## 操作规则

- 禁止在 `paneflow/` 中修改、提交、建分支或推送。
- 禁止把派生提交推送到 `https://github.com/arthjean/paneflow.git`。
- 当前实验阶段禁止在派生仓库执行任何 `git push`。
- 每个实验使用独立本地提交，提交前检查样本仓库仍然干净、派生仓库仍然没有 remote。
- 需要引入新的上游版本时先记录旧基线、目标提交、冲突和验证结果，不直接覆盖当前实验历史。

## 正式迁移条件

只有用户明确确认进入正式开发后，才执行以下操作：

1. 确定 AgentWorkspace 的独立远端仓库和默认分支。
2. 配置新的 `origin`，并核对它不指向 Paneflow 上游。
3. 把 Paneflow GitHub 地址配置为只读 `upstream`，同时设置不可用的 push URL。
4. 迁移项目产品、技术和测试文档，保留本地实验提交及上游版权记录。
5. 经用户再次明确授权后才允许首次推送。
